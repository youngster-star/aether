# 注释检查（comment）

依据：Stage.md §1.1 代码规范（注释清晰简洁，不图省事不写注释）、用户全局规范（中文注释）。

## 检查清单

| 检查点 | 说明 |
| --- | --- |
| 关键逻辑有注释 | 复杂算法/业务规则/非显而易见的设计决策必须有中文注释说明"为什么" |
| 类/方法有 JSDoc/Javadoc | 公共类与公共方法有用途说明（@param/@return 按需，不强制逐参） |
| 注释与代码一致 | 改代码必须同步改注释；注释描述的字段名/行为与实际不符 → FAIL |
| 无冗余注释 | 删除纯复述代码的注释（如 `// 设置名称` 配 `setName()`）；删除注释掉的旧代码块 |
| 无 TODO 堆积 | 新增 TODO 必须带背景说明与责任人；超过 2 周的临时 TODO → 问题项 |
| 语言统一 | 注释用中文（专有名词/代码标识除外），符合项目现有风格 |
| 不掩盖问题 | 禁止用注释解释屎山逻辑而不重构；发现"注释解释烂代码"记问题项 |

## 输出格式

- 问题清单：`文件:行 — 问题类型 — 说明`
- 结论：PASS / FAIL（注释与代码不一致、关键逻辑无注释 → FAIL）
